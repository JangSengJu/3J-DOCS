## 1. 개요

### 1.1 서비스 소개
Costly 는 클라우드(AWS) 리소스를 등록하면 **월 예상 요금을 계산**하고, **예산 한도 초과 여부를 알려주며**, **Gemini AI 가 비용·성능·안정성·보안·확장성·아키텍처 관점의 개선안을 제안**하고 **보고서(PDF)로 정리**해 주는 웹 애플리케이션이다.

### 1.2 목표 사용자
| 사용자 | 설명 |
| --- | --- |
| 개인 개발자 · 학생 | 사이드 프로젝트의 AWS 비용을 점검하고 절감하고 싶은 사용자 |
| 소규모 팀 운영자 | 운영 중인 클라우드 리소스가 예산 대비 적정한지 확인하려는 사용자 |

### 1.3 핵심 가치
| 가치 | 설명 |
| --- | --- |
| 즉시성 | 회원가입 절차 없이 아이디·비밀번호만 입력하면 자동 가입되어 바로 사용 |
| 안전성 | AI 호출이 실패해도 폴백(Fallback)으로 항상 결과 화면 제공 — 화면이 비지 않음 |
| 신뢰성 | 서울 리전 온디맨드 단가 카탈로그 기반으로 비용 계산, 근거와 함께 제안 제공 |

## 3. 사용자 시나리오

```
[접속] → 아이디·비밀번호 입력 → (없으면 자동 가입) → 대시보드
   │
   ├─ 리소스 등록 (유형·옵션·수량/사용시간·사용률·필요도)
   ├─ 사용 용도 입력 / 예산 한도 설정
   │
   ├─ 예산 초과 시 경고 배너 노출 → "절감 추천 확인"
   │
   ▼
[절감 추천 페이지] → AI 분석 실행 → 추천 카드 확인
   │
   ▼
개선 보고서 생성(실시간 스트리밍) → PDF 내보내기
```

## 5. 화면별 상세 기능 명세

### 5.1 로그인 화면

| 항목 | 내용 |
| --- | --- |
| 경로 | `/login` |
| 목적 | 아이디·비밀번호 입력으로 접속 (없으면 자동 가입) |
| 입력 | 아이디(이메일/학번), 비밀번호 |
| 동작 | 제출 시 서버 인증 → 성공 시 토큰 저장 후 `/dashboard` 이동 |
| 상태 | 접속 중(busy) 시 버튼 비활성화 및 "접속 중…" 표시 |
| 예외 | 아이디/비밀번호 미입력, 길이 초과, 비밀번호 불일치 시 서버 오류 메시지 노출 |
| 이동 | 로그인된 사용자가 접근 시 `/dashboard` 로 리다이렉트 |

### 5.2 대시보드 화면

| 기능 | 상세 동작 | 예외/규칙 |
| --- | --- | --- |
| 리소스 목록 | 이름·사양(meta)·필요도·월 요금 표시 | 0건이면 빈 목록 |
| 리소스 등록 | 유형 → 옵션 → 수량/사용시간 → 사용률·필요도·이름 입력 후 등록 | 이름 중복 시 `// {이름} 중복` 메시지, 등록 취소 |
| 수량 입력 분기 | 시간당 과금(hour·lcu_hour)이면 사용시간 선택, 그 외는 수량 숫자 입력 | 사용시간 프리셋: 730h/176h/365h/209h |
| 예상 요금 미리보기 | 등록 폼에서 실시간 예상 월 요금 표시 | 무료 티어 차감 후 계산 |
| 리소스 삭제 | × 버튼으로 삭제, 연결된 AI 노트도 삭제 | 확인 절차 없이 즉시 삭제 |
| AI 노트 | 리소스별 코멘트 입력 토글 (`＋`) | 최대 500자 |
| 사용 용도 | 공통 업무 용도 입력 (최대 1000자) | AI 프롬프트에 반영 |
| 예산 한도 | 월 예산 한도(USD) 입력 후 "적용" | 1 미만이면 무시 |
| 초과 알림 | 합계 > 한도면 "예산 초과" + 초과액 + 추천 링크 | 이하면 "예산 안정" |
| 분석 실행 | "절감 분석 실행" → 절감 추천 화면 이동 | — |
| 등록 모달 | ESC 또는 배경 클릭으로 닫힘 | 이름 중복 시 등록 거부 |

### 5.2.1 리소스 등록 입력 항목

| 필드 | 입력 방식 | 허용값 / 기본값 |
| --- | --- | --- |
| 유형 | 선택 | EC2, EKS, RDS, S3, DynamoDB, ALB, CloudFront 등 20종 |
| 옵션 | 선택 | 유형별 요금 옵션 (예: EC2 → t3.micro ~ c5.large) |
| 수량/사용 시간 | 숫자 또는 선택 | 시간당 과금이면 사용 시간(730/176/365/209h), 그 외 수량 |
| 사용률 | 선택 | `<5%`, `5~20%`, `>20%` |
| 필요도 | 선택 | `대부분 유휴`, `항상 필요` |
| 이름 | 텍스트 (선택) | 미입력 시 `{유형}-{사양}` 자동 생성 |

### 5.3 절감 추천 화면

| 항목 | 내용 |
| --- | --- |
| 경로 | `/recommend` |
| 목적 | AI 절감 추천 확인 → 개선 보고서 생성·내보내기 |
| 상태 | `idle → running → done` (분석), 보고서는 별도 진행 상태 |
| 분석 실행 | 리소스·합계·한도·용도·노트를 서버로 전송, 추천 카드 렌더 |
| 추천 카드 | 순번, 대상 리소스, 유형 태그, 제목, 근거 목록, 예상 월 절감/추가 비용 |
| 요약 바 | 총 추천 건수, 월 합계, 총 절감 후보액, 투자형 제안 건수 |
| 보고서 생성 | 요청 시 실시간(SSE)으로 본문을 받아 렌더링, 진행률 표시 |
| PDF 내보내기 | 보고서를 새 창 인쇄로 PDF 저장 (팝업 차단 시 안내) |
| 폴백 고지 | AI 실패 시 "규칙 기반으로 대체됨" 안내 문구 표시 |

### 5.3.1 추천 카드 표시 규칙

| 항목 | 규칙 |
| --- | --- |
| 유형 배지 | `kind` 를 한국어 라벨로 표시 (절감/성능/안정성/보안/확장성/아키텍처/기타) |
| 비용 표시 | `savings > 0` → "예상 월 절감", `< 0` → "예상 추가 비용", `= 0` → "비용 변동 ±0" |
| 대상 없음 | `target` 이 비면 "전체 리소스" 로 표시 |
| 근거 없음 | 근거가 없으면 기본 문구 노출 (카드가 비지 않음) |
| 최대 개수 | 추천 최대 15건, 같은 변경 방식(action)은 최대 3건 |

### 5.4 보고서 섹션 구성

| 순서 | 섹션 | 내용 |
| --- | --- | --- |
| 1 | 요약 | 총 예상 비용, 예산 대비 초과/이내, 총 절감 후보액 |
| 2 | 비용·아키텍처 현황 | 리소스별 비용·사용률·필요도·구성 |
| 3 | 개선 제안 | 제안 / 유형 / 대상 리소스 / 비용 영향 표 |
| 4 | 세부 검토 | 제안별 근거 |
| 5 | 실행 계획 | 우선순위 검토 → 검증 → 모니터링 |
| 6 | 결론 | 절감 적용 후 예상 비용 |

## 6. 데이터 명세

### 6.1 Resource (등록 리소스)

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| id | string | Y | 리소스 고유 ID (UUID) |
| name | string | Y | 표시 이름 (예: `ec2-m5-large`) |
| type | string | Y | 리소스 유형 (EC2, RDS, S3 등 20종) |
| unit | string | Y | 과금 단위 (hour, month, gb_month 등 8종) |
| cost | number | Y | 월 예상 비용(USD), 등록 시 계산해 저장 |
| usage | string | Y | 사용률 (`<5%`, `5~20%`, `>20%`) |
| need | string | Y | 필요도 (`대부분 유휴`, `항상 필요`) |
| meta | string | N | 사양 요약 (예: `EC2 · m5.large · 730 시간`) |

| 필드 | 타입 | 설명 |

| limit | number | 월 예산 한도(USD) |
| notes | object | `리소스 이름 → AI 노트` 매핑 |
| purpose | string | 공통 사용 용도 (최대 1000자) |

### 6.3 AiRecommendation (AI 제안)

| 필드 | 타입 | 설명 |
| --- | --- | --- |

| savings | number | 월 비용 변동(USD). 양수=절감, 음수=투자, 0=변동 없음 |
| grounds | string[] | 제안 근거 (최대 5개) |
| action | string | 변경 방식 (아래 Enum 참고) |
| kind | string | 제안 대주제 (아래 Enum 참고) |

### 6.4 PublicUser

| 필드 | 타입 | 설명 |
| --- | --- | --- |

## 8. 비기능 요구사항

| 안정성 | AI/키 실패 시 폴백으로 항상 결과 제공 (500 응답 없이 정상 결과) |
| 안정성 | 데이터 저장은 tmp→rename 원자적 쓰기 + 디바운스 |
| 성능 | 예산 저장은 400ms 디바운스로 요청 최소화 |

| 입력 검증 | 서버가 본문을 화이트리스트·상한 기준으로 정규화 (아래 제한 참고) |

## 9. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 리소스 | 비용이 발생하는 클라우드 자원 1건 (예: EC2 인스턴스) |
| 옵션 | 리소스의 사양/등급 (예: t3.micro, m5.large) |
| 과금 단위 | 요금이 매겨지는 기준 단위 (시간, GB·월 등) |
| 절감 후보액 | 추천들의 양수 savings 합계 |
| 폴백 | AI 호출 실패 시 규칙 기반으로 대신 생성한 결과 |
| SSE | Server-Sent Events, 서버가 텍스트를 조각으로 실시간 전송하는 방식 |
