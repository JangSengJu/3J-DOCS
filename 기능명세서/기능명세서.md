## 1. 개요

3J 는 클라우드(AWS) 리소스를 등록하면 **월 예상 요금을 계산**하고, **예산 초과 여부를 알려주며**, **Groq AI 가 개선안을 제안**하고 **보고서(PDF)로 정리**해 주는 웹 서비스다.

3J 는 클라우드(AWS) 리소스를 등록하면 **월 예상 요금을 계산**하고, **예산 초과 여부를 알려주며**, **Groq AI 가 개선안을 제안**하고 **보고서(PDF)로 정리**해 주는 웹 서비스다.

**기술 스택**

| 구분 | 스택 |
| --- | --- |
| 백엔드 | Java 17 + Spring Boot |
| 프런트엔드 | React |
| 인증 | JWT (Access Token + Refresh Token) |
| AI | Groq (서버에서 호출) |

| 목표 사용자 | 설명 |
| --- | --- |
| 개인 개발자 · 학생 | 사이드 프로젝트의 AWS 비용을 점검하고 절감하려는 사용자 |
| 소규모 팀 | 운영 중인 리소스가 예산 대비 적정한지 확인하려는 사용자 |

**핵심 가치**

| 가치 | 설명 |
| --- | --- |
| 안전한 인증 | 회원가입/로그인 분리 + JWT(Access/Refresh) 기반 인증 |
| 무중단 결과 | AI 호출이 실패해도 폴백으로 결과 화면을 항상 제공 |
| 근거 있는 제안 | 서울 리전 단가 카탈로그 기반 계산, 근거와 함께 제안 |

## 2. MVP 범위

| 구분 | 기능 | 포함 |
| --- | --- | --- |
| 인증 | 회원가입, 로그인, JWT 재발급, 로그아웃 | O |
| 대시보드 | 리소스 등록/삭제, 사용 용도, 예산 한도, 초과 알림 | O |
| 비용 | 단가 카탈로그 기반 월 예상 요금 계산 | O |

| 계정 | 비밀번호 변경, 탈퇴, 비밀번호 찾기, 소셜 로그인 | 제외 |
| 연동 | AWS 실 계정 연동, 실 청구 데이터 수집 | 제외 |
| 기타 | 공유 링크, 팀 협업, 결제 | 제외 |

## 2.1 사용자 시나리오

```
[회원가입] → [로그인] → 대시보드
   ├─ 리소스 등록 (유형·옵션·수량/사용시간·사용률·필요도)
   ├─ 사용 용도 입력 / 예산 한도 설정
   ├─ 예산 초과 시 경고 → "절감 추천 확인"
   ▼
[절감 추천] → AI 분석 실행 → 추천 카드 확인
   ▼
개선 보고서 생성(실시간) → PDF 내보내기
```

## 4. 화면별 상세

### 4.1 회원가입 화면

| 항목 | 내용 |
| --- | --- |
| 경로 | `/signup` |
| 목적 | 아이디·비밀번호로 새 계정 생성 |
| 입력 | 아이디, 비밀번호, (선택) 비밀번호 확인 |
| 동작 | 가입 성공 시 로그인 화면으로 이동 |
| 검증 | 아이디/비밀번호 필수, 아이디 중복 시 오류 표시 |

| 검증 항목 | 규칙 |
| --- | --- |
| 아이디 | 4~120자, 공백 제거·소문자 정규화, 중복 불가 |
| 비밀번호 | 8~200자 |

### 4.2 로그인 화면

| 항목 | 내용 |
| --- | --- |
| 경로 | `/login` |
| 입력 | 아이디, 비밀번호 |
| 동작 | Access Token·Refresh Token 발급 후 대시보드 이동 |
| 예외 | 계정 없음/비밀번호 불일치 시 오류 메시지 |

> 자동 회원가입은 없다. 가입되지 않은 아이디로 로그인하면 실패한다.

### 4.3 대시보드 화면

| 기능 | 설명 |
| --- | --- |
| 리소스 등록 | 유형·옵션·수량/사용시간·사용률·필요도 입력, 이름 자동 생성(중복 방지) |
| 리소스 목록 | 이름·사양·필요도·월 요금 표시, 삭제 버튼 |
| AI 노트 | 리소스별 코멘트 (분석 프롬프트에 반영) |
| 사용 용도 | 리소스 공통 업무 용도 입력 |
| 예산 한도 | 월 예산 한도(USD) 설정 |
| 초과 알림 | 합계 > 한도면 초과액 경고, 아니면 안정 표시 |
| 합계 요약 | 리소스 수·월 합계·안정/위험 상태 |

**리소스 등록 입력 항목**

| 필드 | 입력 방식 | 허용값 |
| --- | --- | --- |
| 유형 | 선택 | EC2, EKS, RDS, S3, DynamoDB, ALB 등 20종 |
| 옵션 | 선택 | 유형별 요금 옵션 (예: EC2 → t3.micro ~ c5.large) |
| 수량/사용 시간 | 숫자 또는 선택 | 시간당 과금이면 730/176/365/209h, 그 외 수량 |
| 사용률 | 선택 | `<5%`, `5~20%`, `>20%` |
| 필요도 | 선택 | `대부분 유휴`, `항상 필요` |
| 이름 | 텍스트(선택) | 미입력 시 `{유형}-{사양}` 자동 생성 |

### 4.4 절감 추천 화면

| 기능 | 설명 |
| --- | --- |
| AI 분석 실행 | 리소스·용도·한도를 서버로 전달해 추천 생성 |
| 추천 카드 | 제안·근거·대상 리소스·예상 절감액·유형 배지 |
| 요약 | 총 절감 후보액, 추가 비용(투자) 제안 건수 |
| 보고서 생성 | 6개 섹션 마크다운을 실시간(SSE) 수신해 렌더링 |
| PDF 내보내기 | 브라우저 인쇄로 PDF 저장 |
| 폴백 고지 | AI 실패 시 규칙 기반 결과임을 안내 |

**추천 카드 표시 규칙**

| 항목 | 규칙 |
| --- | --- |
| 유형 배지 | kind 를 한국어 라벨로 표시 |
| 비용 표시 | savings > 0 → "예상 월 절감", < 0 → "예상 추가 비용", = 0 → "±0" |
| 대상 없음 | target 이 비면 "전체 리소스" |
| 최대 개수 | 추천 최대 15건, 같은 action 은 최대 3건 |

**보고서 섹션**

`1. 요약` · `2. 비용·아키텍처 현황` · `3. 개선 제안(표)` · `4. 세부 검토` · `5. 실행 계획` · `6. 결론`

## 5. 데이터 명세

### 5.1 Resource

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID |
| name | string | 표시 이름 (예: `ec2-m5-large`) |
| type | string | 리소스 유형 |
| unit | string | 과금 단위 |
| cost | number | 월 예상 비용(USD) |
| usage | string | 사용률 |
| need | string | 필요도 |
| meta | string | 사양 요약 |

### 5.2 Budget

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| resources | Resource[] | 리소스 목록 (최대 200건) |
| limit | number | 월 예산 한도(USD) |
| notes | object | `리소스 이름 → AI 노트` |
| purpose | string | 공통 사용 용도 |

> 신규 사용자는 **빈 Budget**(리소스 0건)으로 시작한다. 초기 템플릿 리소스는 제공하지 않는다.

### 5.3 AiRecommendation

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| title | string | 제안 제목 |
| target | string | 대상 리소스 이름 |
| savings | number | 월 비용 변동(USD). 양수=절감, 음수=투자, 0=변동 없음 |
| grounds | string[] | 제안 근거 (최대 5개) |
| action | string | 변경 방식 |
| kind | string | 제안 대주제 |

### 5.4 User

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 정규화된 아이디 |
| createdAt | string | 가입 시각 (ISO 8601) |

## 6. Enum 및 상수

**kind (대주제)**: `cost`(절감) · `performance`(성능) · `reliability`(안정성) · `security`(보안) · `scalability`(확장성) · `architecture`(아키텍처) · `other`(기타)

**action (변경 방식)**: `downsizing` · `deletion` · `migration` · `reserved` · `consolidation` · `scaleup` · `tier` · `rightsizing` · `other`

**unit (과금 단위)**: `hour` · `lcu_hour` · `month` · `gb_month` · `gb_transfer` · `gb_second` · `million_requests` · `request`

**사용 시간 프리셋**: 24시간 상시(730h) · 평일 9–18(176h) · 야간 20–08(365h) · 주말만(209h)

## 7. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 보안 | 비밀번호는 BCrypt 해시로 저장, 평문 미보관 |
| 보안 | Access Token 은 짧은 수명(30분), Refresh Token 은 서버 저장·폐기 가능 |
| 보안 | Groq API 키는 서버에서만 사용 (클라이언트 미노출) |
| 안정성 | AI/키 실패 시 폴백으로 항상 결과 제공 |
| 성능 | 예산 저장 400ms 디바운스, 보고서 SSE 스트리밍 |
| 입력 검증 | 서버가 화이트리스트·상한 기준으로 본문 정규화 |
| 호환 | 백엔드 Java 17+ / 프런트엔드 React, 최신 Chrome/Edge/Safari |

**입력 크기 제한**

| 항목 | 상한 |
| --- | --- |
| 리소스 / 추천 | 200건 / 15건 |
| 이름 / 제목 | 120자 / 200자 |
| note / purpose | 500자 / 1000자 |
| 요청 본문 | 2MB |
